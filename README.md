## [ 요약 ]

본 프로젝트는 단순한 기술 구현을 넘어, 환경적 압박과 팀 내 갈등을 **논리적인 소통**으로 해결하며 최선의 결과를 끌어낸 경험입니다.

### [ 직면했던 어려움 ]

- **예기치 못한 인원 결원:** 3인 체제에서 1명이 중도 이탈하며 2인 팀이 되었습니다. 이로 인해 1인당 수행해야 할 과업의 양과 책임감이 두 배로 늘어났습니다.
- **기술적 낯설음:** 컴퓨터공학 전공으로 전과한 후 첫 학기였으며, 아두이노(Hardware)를 처음 접하는 상황에서 오는 기술적 진입장벽이 있었습니다.
- **환경적 제약:** 울산에서 부산까지 왕복하는 장거리 통학생으로서, 오프라인 미팅과 실습 시간을 확보하는 데 있어 효율적인 시간 관리가 절실했습니다.

### [ 갈등 관리와 선제적 실행 ]

프로젝트 진행 중 팀원의 연락 지연과 일정 변경으로 인해 마찰이 발생하기도 했습니다. 그 상황에서 '관계 유지'와 '성과 창출'에 우선순위를 두었습니다.

- **선제적 기여:** 팀원이 다른 활동으로 바쁜 상황임을 인지하고, 행정적인 업무(재고 파악, 조교님 연락 등)와 같은 성가신 일들을 스스로 먼저 처리하며 팀의 추진력을 유지했습니다.
- **냉정한 상황 판단:** 최종 개발 당일, 연락이 닿지 않는 상황에서도 감정에 치우치지 않고 **Gemini를 활용해 설계도를 추출, 검토**하고 기초 틀 ( 우드락으로 제작한 틀 )을 미리 완성해두는 등 프로젝트 중단을 막기 위해 선제적으로 움직였습니다.
- **역지사지(易地思之):** 팀원과 대면했을 때, 비난 대신 상대방이 납땜 작업 중 겪었던 고충(도구 세팅 문제 등)을 먼저 경청함으로써 오해를 풀고 원만한 소통 분위기를 조성했습니다.

### [ 논리적 설득을 통한 역할 재배분 ]

기여도와 역할 분담에 대한 이견이 생겼을 때, 저는 '전체 효율성'을 근거로 팀원을 설득했습니다.

- **이원화 전략:** "해커톤 경험상 두 명이 하나의 코드를 붙잡는 것보다, 각자 전담 구역을 나누는 것이 병합 과정의 오류를 줄이고 속도를 높일 수 있다"는 논리로 업무 분담을 제안했습니다.
- **성장과 공정성 강조:** 제가 짜놓은 기초 코드 위에 팀원이 기능을 추가하는 방식(Code)과 제가 발표 및 문서화(PPT)를 전담하는 방식을 제시했습니다. 이는 팀원에게도 코드 작성 경험을 부여함과 동시에, 역할 분담표상에서도 기여도가 공정하게 보일 수 있는 최선의 선택임을 설득했습니다.

### [ 프로젝트 결과 및 성과 ]

- **성과:** 팀원과의 원만한 합의 끝에 프로젝트에 집중할 수 있었고, 최종 평가에서 **190/190 만점**이라는 최상위 성적을 거두었습니다.
- **성장:** 전과 후 첫 프로젝트에서 임베딩 하드웨어에 대한 자신감을 얻었으며, 갈등 상황에서 감정을 분리하고 논리로 팀을 리딩하는 법을 배웠습니다. 또한, 개인적으로는 발표 훈련까지 겸할 수 있었던 유의미한 시간이었습니다.
